# Alaxee Proxy

一个面向 Microsoft Edge 的轻量级 Manifest V3 代理扩展。它不提供代理节点、不管理订阅，也不替代 Clash/Mihomo；它负责控制 Edge 浏览器流量，并维护浏览器级别的直连白名单与强制代理黑名单。

## 当前版本

- 版本：`0.2.0`
- 目标浏览器：Microsoft Edge（Chromium，Manifest V3）
- 发布方式：Microsoft Edge Add-ons（计划上架）；开发期间也可本地加载解压缩版本
- 运行依赖：无第三方 JavaScript 运行时依赖

## 功能

- **Clash 代理**：使用用户配置的本机地址和 HTTP 或 SOCKS5 端口。
- **直接连接**：让 Edge 不使用浏览器代理。
- **跟随系统代理**：让 Edge 使用 Windows 系统代理设置。
- **当前网站规则**：从当前标签页一键加入直连白名单，或加入强制经 Clash 的代理黑名单。
- **子域名选项**：白名单和黑名单均可选择仅当前主机名，或同时匹配主域名及其子域名。
- **规则优先级**：代理黑名单优先于白名单；黑名单用于覆盖上级白名单的例外域名。
- **逐标签页状态图标**：工具栏按当前网页实际的浏览器路由显示 XEE 状态图形：交给 Clash、浏览器直连（包括白名单）、系统代理或状态未知。首次点击「加入直连白名单」时会请求可选的 `tabs` 权限；允许后，所有标签页自动按网址更新图标。未授权时工具栏显示“未知”，不会拿全局模式冒充当前网页状态。也可以在面板中单独启用。
- **二级菜单**：将概览与域名规则分开，规则页面再切换直连白名单和代理黑名单，避免主界面无限增长。
- **本地代理配置**：代理地址、端口、协议、模式和域名规则保存在 `chrome.storage.local`；机器专属端点不会上传。\n- **ALAXEE 统一账号**：可使用 ALAXEE Start 中已有的邮箱/密码登录同一个 Supabase 用户身份；密码不会保存在扩展中。\n- **云端规则同步**：当前版本尚未启用；白名单和黑名单仍只在本机保存。登录不会自动上传或下载规则。
- **完整设置中心**：复用快捷面板的同一套交互与控制逻辑，提供更宽的页面布局；两者不会维护两份独立配置。

## 与 Clash/Mihomo 的关系

在 **Clash 代理** 模式下，扩展将 Edge 的浏览器代理设置指向你配置的本机监听地址。普通网站仍由 Clash/Mihomo 按其现有的 `rule`、节点组和策略处理。扩展不会读取、修改或复制 Clash 的 YAML、订阅或规则集。

建议优先使用 Clash/Mihomo 的 **Mixed Port**，扩展默认选择 `SOCKS5`。Mixed Port 同时接受 SOCKS5 与 HTTP 客户端连接，所以使用同一个 Mixed Port 端口即可；如果你使用单独的 HTTP 端口，也可以手动选择 `HTTP`。HTTP 与 SOCKS5 都会进入相同的 Clash 规则引擎，协议本身不保证哪一种一定更快；这里默认 SOCKS5 是兼容性与连接习惯上的默认选择，不是速度承诺。

默认地址和端口 `127.0.0.1:7890` 只是常见示例，必须以 Clash 客户端当前的端口设置为准。不同客户端、不同配置的端口可能不同。

### 直连白名单的优先级

域名规则由 Chromium PAC 脚本在浏览器代理层执行。命中白名单的网站会绕过浏览器代理；命中黑名单的网站会强制通过配置的本机 Clash 端口；未命中任何规则的网站遵循全局模式。扩展不会修改 Clash 自己的 YAML、订阅或分流规则。

启用“包含子域名”时，规则会匹配 `example.com` 及其子域名。两类规则重叠时，黑名单优先，因此可以用 `api.example.com` 的黑名单覆盖 `example.com` 的宽泛白名单。

全局 Clash 模式下，默认走 Clash，白名单例外直连；全局直连模式下，默认直连，黑名单例外走 Clash。系统代理模式直接交给 Windows 系统代理，域名规则暂时不生效，因为 PAC 脚本不能可靠地把未命中的请求重新委托给 Windows 的系统代理实现。

**注意：** 如果 Clash/Mihomo 同时启用了 TUN、系统透明代理或其他网络接管方式，浏览器的 DIRECT 不一定意味着数据包完全绕过 Clash/TUN。那需要结合你的 Clash 模式和路由配置单独确认。

## 本地安装到 Edge

1. 解压发布包到固定目录，例如 `C:\AData\Projects\Alaxee-Proxy`。
2. 在 Edge 地址栏打开 `edge://extensions`。
3. 打开 **开发人员模式**。
4. 点击 **加载解压缩的扩展**。
5. 选择能直接看到 `manifest.json` 的项目文件夹。
6. 将 Alaxee Proxy 固定到工具栏。
7. 点击扩展图标打开快捷面板；面板内可以切换代理、快速修改代理端口并管理当前网站规则。
8. 点击面板右上角「设置」打开完整设置中心。完整设置与快捷面板共用同一套代理模式、连接和白/黑名单控制，不会出现两个页面功能不一致。

## 权限说明

| 权限 | 用途 |
| --- | --- |
| `proxy` | 设置 Edge 浏览器代理模式、PAC 域名路由及代理例外。 |
| `storage` | 本地保存设置和直连白名单。 |
| `activeTab` | 用户点击扩展时读取当前标签页 URL，以便快捷添加当前网站；不申请全站内容访问权限。 |
| `tabs`（可选） | 用户首次添加直连白名单时会请求，或可在面板中主动启用。授权后读取标签页 URL，并按每个页面的实际浏览器路由更新工具栏图标和悬停标题；未授权时显示未知状态；仅本地处理，不读取页面内容、不上传数据。 |\n| `host_permissions`（固定域名） | 仅访问 `kystcwxlqqzgjbdhdmap.supabase.co`，用于向共享 ALAXEE Supabase Auth 服务提交登录请求、刷新会话和验证用户。 |

扩展不申请 `webRequest`、剪贴板或 `identity` 权限；仅请求访问 ALAXEE 的固定 Supabase 项目域名，用于账户登录、刷新会话和验证当前用户。没有远程脚本或遥测。

## 开发与测试

要求 Node.js 20+ 和 Python 3。无需安装 npm 依赖。

```bash
npm test
npm run check
python -m json.tool manifest.json > /dev/null
npm run package:extension
```

`npm run package:extension` 会在 `dist/` 生成仅包含扩展运行文件的商店 ZIP，不会把测试、文档和 Git 元数据打进商店包。

## 发布和自动更新

- 初次上架：必须在 Microsoft Partner Center 创建 Edge Add-ons 产品、填写商店信息和隐私/权限声明，并提交首次审核。
- 商店用户更新：首次发布后，Edge 通过商店机制自动向用户提供审核通过的更新。
- 开发者自动发布：项目包含 GitHub Actions。首次上架完成、启用 Edge Add-ons Publish API 并在仓库配置密钥后，推送匹配版本的 `vX.Y.Z` 标签会自动运行测试、构建商店 ZIP，并将新包提交给 Microsoft 审核。
- 自动化提交不等于审核通过或立即上架；Microsoft 仍控制认证和发布时间。

完整步骤见 [`docs/EDGE-ADDONS-PUBLISHING.md`](docs/EDGE-ADDONS-PUBLISHING.md)。商店列表草稿见 [`STORE-LISTING.md`](STORE-LISTING.md)，隐私说明见 [`PRIVACY.md`](PRIVACY.md)。

## 已知边界

- 代理设置是 **Edge 配置级别** 的，不是只作用于当前标签页。
- 加入白名单会影响 Edge 中访问该主机名的所有标签页和请求，而不只是添加时所在的标签页。
- `edge://`、扩展商店等受限页面、`file://` 本地文件不能加入当前网站白名单；这类页面显示未知状态图形。
- 未启用可选 `tabs` 权限前，工具栏显示未知状态，不会把全局模式冒充成当前网页路由。允许后，工具栏按每个标签页的白名单、黑名单和全局模式分别更新。
- 扩展不能仅凭代理设置判断 Clash 进程是否存活；状态显示的是浏览器当前代理配置，不是对 Clash 服务端的健康检查。
- 其他代理扩展、组织策略或浏览器管理策略可能占用代理设置控制权。若出现冲突，应关闭其他代理扩展或检查管理策略。
- 当前版本不支持代理认证账号密码、PAC 规则编辑、订阅导入、分应用代理和云同步。账户登录与规则云同步仍在独立设计中。

## 安全原则

- 只连接用户自行配置的代理监听地址。
- 默认绑定 loopback (`127.0.0.1`)，不要求 Clash 开启 LAN 访问。
- 不读取代理订阅、不收集浏览记录、不上传白名单。
- 不使用远程代码或动态代码执行。
- Edge Add-ons API 凭据必须保存在 GitHub Actions Secrets，不能提交到代码仓库。
